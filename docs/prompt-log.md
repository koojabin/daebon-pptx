# 프롬프트 개선 기록

발표 자료의 "프롬프트 개선 과정" 슬라이드에 쓰기 위한 기록이다.
의미 있는 프롬프트 변경, AI가 틀린 코드를 줘서 고친 경험을 날짜와 함께 짧게 남긴다.

## 2026-11-24 — 프롬프트 v1 (첫 설계)

- **역할 분리**: 시스템 프롬프트에는 역할(발표 코치)과 출력 규칙(JSON만, 코드블록 금지)만, 사용자 프롬프트에는 발표 정보·작성 규칙·출력 형식·슬라이드 내용을 순서대로 넣었다.
- **시간 맞추기**: "5분 분량으로"라고만 하면 AI가 길이를 잘 못 맞추므로, 분당 280자 기준으로 **목표 글자 수(공백 제외)**와 **목표 초**를 숫자로 계산해 프롬프트에 넣었다. 화면에서도 같은 기준으로 다시 계산해 AI의 예상 시간과 비교한다.
- **환각 방지**: 슬라이드에 없는 수치를 지어내지 말고 `[실제 수치 확인 필요]`처럼 표시하게 했다. 근거·수치를 중시하는 교수님 앞에서 틀린 숫자를 말하는 사고를 막기 위해서다.
- **말투**: "발표체/친근하게"라는 단어만 주지 않고 어미(~습니다 / ~요)까지 구체적으로 지시했다.
- **예상 질문**: "질문 3~5개"만 쓰면 일반적인 질문이 나오므로, 근거가 약한 주장·생략된 설명·한계점 같은 **파고들 지점**을 고르게 했다.

## 2026-11-24 — 코드 쪽 방어 처리

- AI가 JSON 앞뒤에 ```json 코드블록이나 설명 문장을 붙이는 경우가 있어, 첫 `{`부터 마지막 `}`까지 잘라 파싱하도록 했다. 그래도 실패하면 원문을 보여 주고 다시 시도 버튼을 띄운다.
- AI가 일부 슬라이드를 빠뜨리는 경우를 대비해, 슬라이드 번호 기준으로 맞춰 보고 빠진 슬라이드는 "대본 없음"으로 표시한다.
- 최신 Claude 모델은 응답에 thinking 블록이 섞여 올 수 있어 `text` 블록만 모아 쓰도록 했다.

## 2026-11-24 — pptx 스킬로 발표 자료 제작 (`docs/발표자료.pptx`)

- Claude Code의 pptx 스킬로 발표 자료 11장을 코드(pptxgenjs)로 생성했다. 앱과 같은 주황색과 번호 원 모양을 써서 통일감을 맞췄고, 모든 슬라이드에 발표자 노트를 넣어 앱의 노트 추출 기능도 시연할 수 있게 했다.
- **AI가 틀린 부분**: 첫 결과물에서 한글 단어가 줄 끝에서 잘렸다("확/인", "방/향"). PowerPoint로 슬라이드를 이미지로 뽑아 확인하는 과정에서 발견했고, 문장을 줄이고 줄바꿈 위치를 직접 지정해 고쳤다. → AI 결과물은 반드시 눈으로 검수해야 한다는 사례.
- 만든 자료를 우리 앱의 파서에 그대로 넣어 11장 텍스트와 노트가 모두 추출되는 것을 확인했다.

## 2026-11-24 — code-review 스킬로 코드 점검

AI가 짠 코드를 AI(code-review 스킬)에게 다시 리뷰시켰더니 10건(중요 6, 사소 4)이 나왔고 모두 고쳤다. 직접 테스트할 때는 못 찾은 것들이다.

- **다른 PPT를 올리면 이전 결과가 남아 섞임** → 새 파일을 올리면 결과를 비우고, 결과마다 파일 이름을 따로 저장
- **생성 중에 파일을 바꾸면 결과가 엉뚱한 슬라이드 수로 만들어짐** → 요청 시점의 슬라이드를 고정하고, 생성 중 업로드 차단
- **슬라이드 번호·바닥글 글자까지 본문으로 읽음** → 이미지만 있는 슬라이드가 "텍스트 없음"으로 안 잡히던 문제. 자리표시자 제외
- **숨긴 슬라이드까지 대본에 포함** → `show="0"` 슬라이드 제외
- **같은 파일을 다시 고르면 반응 없음** → 파일 입력값 초기화
- **.txt 다운로드가 일부 브라우저에서 실패할 수 있음** → 다운로드 URL을 바로 해제하지 않고 잠시 뒤 해제
- 그 밖에: 모든 오류를 "네트워크 오류"로 보여 주던 문제, OpenAI 거절 응답 처리, 발표 시간 1~120분 검사, 복사 실패인데 "복사됨!"이 뜨던 문제
